# 완료 마일스톤 기록

마지막 수정: 2026-08-03

완료된 마일스톤의 범위와 검증 결과를 보존한다. 현재 작업 범위와 다음 순서는
`docs/PLAN.md`를 기준으로 확인한다.

### M0 — 기반 구성 — 완료

- [x] pnpm 모노레포 구성
- [x] Next.js 웹 애플리케이션 추가
- [x] Kotlin/Spring Boot API 추가
- [x] Docker Compose로 로컬 PostgreSQL 구성
- [x] Flyway와 Spring Data JDBC 의존성 추가
- [x] `/health`와 웹–API 연결 상태 확인 추가
- [x] 웹과 API 빌드 검증

### M1 — 거래내역 vertical slice — 완료

결과: 실제 데이터베이스와 UI를 통해 거래내역을 직접 등록하고 조회할 수 있다.

- [x] 첫 `transactions` 스키마를 Flyway migration으로 정의
- [x] 거래 영속 모델과 Repository 정의
- [x] `POST /transactions` 구현
- [x] `GET /transactions` 구현
- [x] 양의 정수 KRW 금액과 필수 필드 검증
- [x] Repository와 HTTP 테스트 추가
- [x] 웹에서 거래 목록 표시
- [x] 최소한의 수동 거래 등록 폼 추가
- [x] 로컬 PostgreSQL을 사용한 전체 흐름 검증

초기 거래 필드:

- `id`
- `merchant`
- 정수 KRW인 `amount`
- `category`
- timezone을 포함한 `occurred_at`
- `created_at`

M1에서는 Controller → 영속 계층 → 데이터베이스 → UI 흐름을 먼저 학습할 수 있도록
household 소유권과 결제자 정보는 M2로 미룬다.

- [x] `users`, `auth_identities`, `households`, `household_memberships` 스키마 추가
- [x] 인증 제공자와 제공자 고유 ID 조합으로 로그인 계정을 식별
- [x] 웹 애플리케이션에 Google 로그인 추가
- [x] Google 계정 두 개만 허용
- [x] API 경계에서 사용자 신원 검증

- [x] 로그인 실패 원인을 안내하고 allowlist에서 제거된 계정의 기존 세션 차단
- [x] 모든 거래를 household에 연결
- [x] 구조와 테스트를 통해 다른 household 데이터 접근 방지

- [x] 전체, 로그인 사용자, 배우자 기준 거래 필터 추가

결과: 사용자가 짧은 자연어 대화로 거래 초안을 완성하고 확인 후 저장할 수 있다.

- [x] 자연어 거래 입력 UI 추가
- [x] 자연어에서 가맹점, 금액, 카테고리, 발생 시각을 구조화된 초안으로 추출
- [x] 누락된 필수값 재질문 지원
- [x] 현재 초안의 수정, 저장 확인, 취소 지원
- [x] 거래 입력 외 요청을 `unsupported`로 분류하고 지원 범위 안내
- [x] AI 출력을 명시적인 스키마와 서버 비즈니스 규칙으로 검증
- [x] 사용자 확인 전에는 거래를 저장하지 않음
- [x] 대표적인 한국어 입력, 누락값, 지원하지 않는 요청에 대한 API 테스트 추가
- [x] AI 초안을 수정·저장·취소하는 웹 흐름 테스트 추가
- [x] AI 요청 횟수, 실패 상태, 비용 제한을 사용자에게 예측 가능하게 처리
- [x] 카드·현금 결제수단과 국내 카드사 입력을 수동·AI 거래 입력에 추가
- [x] AI 초안에서 카드·현금·QR 결제 경로와 상품권·바우처 잔액 계정을 분리
- [x] 구매 품목이나 사용 목적을 남기는 선택 내역을 수동·AI 거래 입력에 추가

### M4 — 일·주·월 지출 통계 — 완료

결과: 선택한 일간, 주간, 월간 기간의 지출 규모와 구성을 한눈에 확인할 수 있다.

- [x] `Asia/Seoul` 기준 일간, 주간, 월간 범위와 이전 비교 기간 정의
- [x] household로 격리된 기간별 합계와 거래 건수 쿼리 추가
- [x] 이전 기간 대비 금액과 증감률 계산
- [x] 결제자, 결제수단, 현재 카테고리 기록 기준의 지출 구성 집계
- [x] 전체, 로그인 사용자, 배우자 기준으로 모든 통계와 이전 기간 비교 필터
- [x] 웹의 `/stats`에서 기간 종류와 기준 날짜를 선택하는 통계 화면 추가
- [x] 합계, 거래 건수, 이전 기간 비교와 지출 구성을 이해하기 쉽게 표시
- [x] 빈 기간, 날짜 경계, household 격리, 합계와 구성에 대한 테스트 추가

초기 카테고리는 자유 입력 값이므로 같은 성격의 지출이 여러 이름으로 나뉠 수 있다.
M4에서는 저장된 값을 그대로 집계하고, 표준 분류와 태그를 도입하는 M6 이후 정교한
카테고리 비교를 제공한다.

결과: 월별 카드 명세서를 업로드해 기존 거래의 누락, 중복 의심, 불일치를 검토하고
선택한 항목만 반영할 수 있다.

- [x] 첫 번째 형식으로 KB국민카드 이용대금명세서 XLSX 확정
- [x] 현대카드 HTML 기반 XLS와 온누리상품권 청구할인 연결 지원
- [x] 파일 형식과 필수 열을 검증하고 지원하지 않는 파일에 오류 안내
- [x] 명세서 행을 정규화된 거래 후보로 변환
- [x] 금액, 날짜, 가맹점명을 사용하는 결정적인 대조 기준 정의
- [x] 대조 결과를 일치, 누락, 중복 의심, 불일치로 분류
- [x] 사용자가 선택한 누락 거래만 데이터베이스에 반영
- [x] 불일치 후보에서 사용자가 확정한 기존 거래 수정 사항 반영
- [x] 같은 명세서를 다시 업로드해도 거래가 중복 생성되지 않도록 구현
- [x] 처리 완료 후 원본 파일을 폐기하고 로그에 명세서 원문을 남기지 않음
- [x] 정상 파일, 잘못된 파일, 재업로드, 각 대조 결과에 대한 테스트 추가
- [x] 웹의 `/statements`에서 업로드, 대조, 누락 선택과 저장 흐름 제공
