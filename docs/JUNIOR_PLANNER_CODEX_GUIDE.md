# 주니어 기획자를 위한 우리집 Codex 가이드

개발을 몰라도 괜찮다. Codex는 우리집 프로젝트를 이해하고, 아이디어를 개발자가
작업할 수 있는 GitHub Issue로 정리하는 데 사용한다.

## 시작 전에

- 자신의 OpenAI 계정으로 Codex에 로그인한다. 무료 계정으로 시작해도 된다.
- 자신의 GitHub 계정과 Figma 계정으로 프로젝트에 참여한다.
- 개발자에게 우리집 저장소를 Codex에서 열 수 있게 준비해 달라고 요청한다.
- 계정, 비밀번호, API 키는 공유하거나 Codex에 입력하지 않는다.

## 처음 할 일

Codex에서 우리집 저장소를 연 뒤 아래 내용을 그대로 요청한다.

```text
나는 이 프로젝트에 처음 참여한 주니어 기획자야.
AGENTS.md와 docs/PLAN.md를 읽고 파일은 수정하지 마.

다음 내용을 개발 용어를 줄여서 설명해줘.
1. 우리집이 해결하려는 문제
2. 지금까지 완성된 기능
3. 현재 진행 중인 마일스톤
4. 앞으로 결정해야 할 기획 항목
```

제품 범위와 진행 상태는 `docs/PLAN.md`를 기준으로 확인한다.

## 아이디어를 Issue로 정리하기

아이디어가 생기면 완성된 문장으로 만들려고 고민하지 말고 Codex에 먼저 전달한다.

```text
다음 아이디어를 우리집의 현재 마일스톤과 비교해줘.

[아이디어를 편하게 작성]

아래 항목으로 GitHub Issue 초안을 만들어줘.
- 해결하려는 문제
- 대상 사용자
- 사용 흐름
- 포함 범위
- 제외 범위
- 완료 조건
- 결정이 필요한 질문

현재 마일스톤 밖의 내용은 별도로 표시하고, 정해지지 않은 정책은 추측하지 마.
파일은 수정하지 마.
```

Codex가 만든 초안에서 다음 내용을 직접 확인한다.

- 사용자가 왜 이 기능을 필요로 하는가
- 어디서 시작해서 어떤 결과를 보게 되는가
- 성공했을 때와 실패했을 때 화면이 어떻게 달라지는가
- 이번 작업에서 하지 않을 것은 무엇인가
- 아직 담당자와 결정해야 할 것은 무엇인가

## 빠진 정책 찾기

Issue 초안을 만든 뒤 아래 요청으로 빠진 내용을 점검한다.

```text
이 Issue를 기획 관점에서 검토해줘.

다음 항목에서 빠진 정책과 애매한 표현을 찾아줘.
- 처음 사용하는 경우
- 데이터가 없는 경우
- 처리 중인 경우
- 실패한 경우
- 권한이 없는 경우
- 취소하거나 다시 시도하는 경우

반드시 결정해야 하는 항목과 개발 중 결정해도 되는 항목을 나눠줘.
```

Codex가 제안한 내용은 확정된 정책이 아니다. 제품 범위를 바꾸거나 선택지가 여러
개라면 담당자와 결정한 뒤 Issue에 반영한다.

## Figma와 함께 확인하기

화면 작업은 Figma 링크와 Issue를 Codex에 함께 제공한다.

```text
이 Figma 화면과 Issue의 완료 조건이 서로 맞는지 확인해줘.

다음을 나눠서 알려줘.
- Issue에는 있지만 화면에 없는 내용
- 화면에는 있지만 Issue에 없는 내용
- 오류, 빈 상태, 로딩 상태처럼 추가로 필요한 화면
- 기획자가 결정해야 할 질문

코드 구현은 요청하지 마.
```

Codex가 Figma에 접근할 수 없다면 화면 캡처나 필요한 화면 설명을 함께 제공한다.

## 개발 결과 확인하기

개발자가 Pull Request를 만들면 PR 설명과 Issue를 기준으로 확인한다.

```text
이 Pull Request가 Issue의 완료 조건을 충족하는지 기획자 관점에서 검토해줘.

코드 문법보다 다음 내용을 확인해줘.
- 사용 흐름이 Issue와 같은가
- 빠진 성공, 실패, 빈 상태가 있는가
- Figma와 다른 사용자 문구나 동작이 있는가
- 직접 화면에서 확인할 항목은 무엇인가

확인된 사실과 직접 실행해 봐야 하는 항목을 구분해줘.
```

Codex의 설명만으로 검수를 끝내지 않는다. 실제 화면에서 주요 흐름과 오류 상황을
직접 확인한다.

## Issue 기본 형식

```markdown
## 해결하려는 문제

## 대상 사용자

## 사용 흐름

## 포함 범위

## 제외 범위

## 완료 조건
- [ ]

## 디자인
- Figma:

## 결정이 필요한 질문
```

## 이것만 지키기

- 하나의 Issue에는 하나의 사용자 문제만 담는다.
- 현재 마일스톤 밖의 아이디어는 기존 작업에 섞지 않는다.
- 정해지지 않은 정책을 Codex가 임의로 결정하게 두지 않는다.
- 기획 업무 중에는 Codex에 파일 수정, 커밋, push를 요청하지 않는다.
- 비밀번호, 개인정보, 실제 결제 정보는 입력하지 않는다.
- 최종 기준은 합의된 GitHub Issue, Figma와 `docs/PLAN.md`다.
