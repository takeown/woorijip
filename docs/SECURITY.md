# 보안 기준

마지막 수정: 2026-08-03

우리집의 데이터 경계, 외부 전송, 비밀값과 보안 검증 기준을 정의한다. 짧고 항상
적용해야 하는 금지 규칙은 루트 `AGENTS.md`에 두고, 보안 설계와 테스트의 기준은 이
문서가 소유한다.

## 적용 시점

다음 영역을 변경할 때 관련 항목을 작업 전에 읽고, 변경 결과에 보안 영향과 실행한
음성 테스트를 기록한다.

- 인증, 세션, CSRF, CORS와 공개 엔드포인트
- household 소유 데이터의 조회·생성·수정·삭제
- 외부 AI나 다른 외부 서비스 연동
- 카드 명세서 등 사용자 파일 업로드
- 로그, 오류 응답, 메트릭과 운영 진단
- 환경변수, 비밀값, 배포 workflow와 네트워크

## 데이터 분류

| 분류 | 예시 | 기준 |
| --- | --- | --- |
| 인증 비밀 | OAuth 토큰, 세션 ID, API 키, SSH 키, 비밀번호 | 로그·오류·커밋·외부 AI에 포함하지 않고 서버 비밀값으로만 관리 |
| 금융·고유식별 정보 | 전체 카드번호, 계좌번호, 주민등록번호 | 현재 제품에는 저장하지 않고 외부 서비스에도 전송하지 않음 |
| 개인정보 | 실명, 이메일, 전화번호, 외부 제공자 사용자 ID | 기능에 꼭 필요한 경계 안에서만 사용하고 외부 전송은 기본 금지 |
| 가계 데이터 | 거래, 가맹점, 금액, 내역, 명세서 후보 | household로 격리하고 로그와 오류에 원문을 남기지 않음 |
| 업로드 원본 | 카드 명세서 파일과 원본 행 | 요청 처리 중에만 사용하고 영구 저장하지 않음 |
| 비민감 설정 | 공개 도메인, 포트, 모델 이름 | 공개 가능 여부를 값별로 판단하며 비밀값과 같은 파일에 섞였다고 공개하지 않음 |

새 데이터가 어느 분류인지 불명확하면 저장하거나 외부로 보내기 전에 사용자와 필요성을
확인한다. 민감정보 저장이 불가피하면 애플리케이션 계층에서 암호화하고 키를 코드와
데이터베이스에서 분리한다.

## 인증과 세션

- `/health`, `/actuator/health`, `/auth/csrf`, OAuth 로그인 경로처럼 명시적으로 공개한
  엔드포인트 외에는 인증을 요구한다.
- 상태 변경 요청의 CSRF 보호를 끄지 않는다. 웹은 CSRF 쿠키의 토큰을 헤더로 전달한다.
- 운영 세션 쿠키는 `Secure`, `HttpOnly`, `SameSite=Lax`를 유지한다.
- CORS는 환경변수로 지정한 정확한 origin과 필요한 메서드만 허용한다.
- Google allowlist는 최초 로그인뿐 아니라 인증된 요청마다 확인한다. 제거된 계정의
  기존 세션은 더 이상 사용할 수 없어야 한다.
- 인증 실패 응답과 OAuth redirect에는 토큰, 이메일, 내부 예외 원문을 포함하지 않는다.

인증 또는 세션 변경에는 최소한 공개 경로, 비인증 요청, 허용 계정, 거부 계정, 로그아웃,
CSRF가 없는 상태 변경 요청을 검증한다.

## Household 권한 경계

- household는 가계 데이터의 소유권과 접근 제어 경계다.
- 현재 household는 클라이언트 입력이 아니라 인증된 `CurrentUser`에서 결정한다.
- 가계 데이터의 조회·집계·수정·삭제 쿼리는 ID만 사용하지 않고 `household_id` 조건을
  함께 사용한다.
- 결제자나 연관 객체 ID를 받을 때 현재 household 구성원 또는 소유 데이터인지 서버에서
  다시 검증한다.
- 상품권·바우처 계정의 `owner_user_id`는 현재 household 구성원이어야 한다. 사용자별
  소유 표시는 잔액을 구분하는 기준이며 별도 접근 제어 경계는 아니므로 같은 household
  구성원은 서로의 잔액을 조회하고 거래에 선택할 수 있다. 계정 생성·수정·보관·삭제와
  충전 요청도 인증된 household 조건으로 다시 조회하며 다른 household의 ID는 404로 처리한다.
- 응답 DTO에는 다른 household 데이터나 내부 소유권 식별자를 불필요하게 노출하지 않는다.

가계 데이터 변경에는 같은 household의 성공 테스트와 다른 household의 조회·수정·삭제
거부 테스트를 함께 둔다.

## 외부 서비스와 AI

외부 서비스는 제공자의 데이터 공유 설정과 관계없이 별도 보안 경계로 취급한다.

- 기능 수행에 필요한 필드만 명시적으로 구성해 전송한다.
- 카드번호, 계좌번호, 주민등록번호, OAuth 토큰과 인증정보는 전송하지 않는다.
- 실명, 이메일, 전화번호와 내부 원본 식별자는 꼭 필요한 경우가 아니면 전송하지 않는다.
- 사용자 자유 입력에 금지 데이터가 포함될 수 있으면 외부 요청 직전에 서버가 탐지해
  거부하거나 제거한다. 프롬프트 안내만으로 보호하지 않는다.
- 외부 서비스가 안정적인 사용자 식별자를 요구하면 원본 ID 대신 별도 비밀키로 만든
  HMAC 가명 식별자를 사용한다.
- 외부 응답은 신뢰하지 않고 명시적인 스키마와 서버 비즈니스 규칙으로 다시 검증한다.
- 연결·응답 시간과 사용량을 제한하고 실패 응답에 요청 원문을 포함하지 않는다.

현재 OpenAI 거래 초안 요청은 `AiSensitiveInputGuard`를 통과한 사용자 메시지 원문과
현재 시각, 허용된 거래 필드·분류 목록을 전달한다. 내부 사용자 ID는
`OpenAiSafetyIdentifier`가 HMAC-SHA256으로 가명화한 `safety_identifier`로 전달한다.
사용자 메시지에서 거래를 구조화해야 하므로 원문 전송은 필요하지만, 실명·이메일 같은
불필요한 개인정보나 인증·금융 비밀이 포함된 요청은 전송 전에 거부한다. Responses API의
`store: false`를 유지하며 AI는 거래를 직접 저장하지 않는다.

## 파일 업로드

- 현재 카드 명세서 요청과 파일 크기는 모두 2MB 이하로 제한한다.
- 확장자와 `Content-Type`만 신뢰하지 않고 parser가 실제 파일 구조와 필수 항목을 검증한다.
- 새 형식을 지원할 때 행 수, 셀 크기, 압축 해제량과 처리 시간처럼 형식에 맞는 자원
  제한을 정한 뒤 활성화한다.
- 원본 파일과 원본 행은 영구 저장하거나 로그에 남기지 않는다.
- 재업로드 판별에는 원본 대신 정규화된 논리 내용의 fingerprint를 사용한다.
- 실패하거나 사용자가 적용하지 않은 경우에도 원본을 보관하지 않는다.
- 사용자가 확정한 후보만 거래에 반영하며 적용 직전에 권한과 현재 상태를 다시 검증한다.

파일 업로드 변경에는 빈 파일, 크기 초과, 잘못된 형식, 손상된 내용, 재업로드, 다른
household 접근과 부분 실패를 검증한다.

## 로그와 오류

- 사용자 자유 입력, 거래 내역, 명세서 원문, 외부 AI 요청·응답 원문을 로그에 남기지 않는다.
- 토큰, 쿠키, Authorization 헤더, API 키, 비밀값과 개인정보를 기록하지 않는다.
- 오류 응답은 안정적인 코드와 안전한 안내만 제공하고 내부 예외, SQL, 파일 원문을
  그대로 노출하지 않는다.
- 운영 로그를 공유하기 전에 비밀값, 개인정보와 거래 원문 포함 여부를 다시 확인한다.
- 보안 탐지 횟수가 필요하면 원문 대신 제한된 사유 코드와 집계값만 기록한다.

## 비밀값과 배포

- 실제 비밀값은 코드, 예제 환경변수, Docker 이미지와 커밋 파일에 넣지 않는다.
- 운영 애플리케이션 비밀값은 Lightsail의 권한 제한된 `deploy/.env`에만 둔다.
- GitHub Actions 권한은 job에 필요한 최소 범위로 제한하고 AWS 접근에는 OIDC 단기
  자격 증명을 사용한다.
- SSH 방화벽은 runner의 정확한 `/32`만 임시 허용하고 성공·실패와 관계없이 제거한다.
- 새 비밀값을 추가하면 로컬·운영 설정 이름, 안전한 예제 값, 누락 시 실패 동작과 회전
  방법을 함께 검토한다.
- 비밀값이 노출됐다고 의심되면 값을 폐기·회전한 뒤 로그와 커밋 이력을 별도로 점검한다.

구체적인 운영 절차와 rollback은 `docs/operations/DEPLOYMENT.md`를 따른다.

## 변경 검증 체크리스트

보안 관련 변경에서는 해당하지 않는 항목을 제외하고 다음을 확인한다.

- 신뢰 경계와 새 데이터 흐름을 문서화했다.
- 인증되지 않은 요청과 다른 household 접근을 테스트했다.
- 외부 전송 필드가 최소화됐고 금지 데이터가 요청 전에 차단된다.
- 로그와 오류 응답에 민감한 원문이 노출되지 않는다.
- 업로드와 외부 요청 실패 후 불필요한 데이터가 남지 않는다.
- 새 비밀값이 예제와 운영 설정에 반영되고 실제 값은 저장소에 없다.
- 실행한 테스트와 각 테스트가 보장하지 못하는 범위를 작업 결과에 기록했다.
