# 우리집 개발 계획

마지막 수정: 2026-08-06

## 목표

평소에는 수동 폼이나 자연어로 거래를 기록하고, 월말에는 카드 명세서 엑셀을
업로드해 누락과 오류를 보정할 수 있는 부부 전용 비공개 가계부를 만든다.

이 프로젝트는 Kotlin과 Spring Boot를 배우는 목적도 있다. 프레임워크의 복잡한
기능을 추가하기 전에, 백엔드의 선택을 이해하고 테스트할 수 있는 작은 end-to-end
기능을 차례대로 완성한다.

## 제품 범위

- 초기에는 허용된 Google 계정 두 개만 접근한다.
- 두 계정은 하나의 household에 속하며 거래내역을 공유한다.
- 데이터 모델은 여러 부부가 각자의 household를 가질 수 있도록 구성하고, 모든 가계
  데이터는 household 경계로 격리한다.
- 인증 계정은 사용자와 분리해 관리한다. 초기에는 Google 로그인만 제공하고 이후
  Kakao와 Naver 로그인을 같은 사용자에게 연결할 수 있도록 한다.
- 거래는 수동 폼, AI 자연어 입력, 카드 명세서 엑셀 대조를 통해 기록한다.
- 육아 지출은 별도 분류하고, 상품권·바우처·지역화폐와 직접 이름 붙인 종류는 필요한
  구성원에게 사용자가 잔액 계정을 만들며 충전·지급·사용·수동 조정을 구분해 관리한다.
- AI 채팅은 한 건의 거래 초안을 작성하고 수정·확정·취소하는 흐름만 지원한다.
- 분석 질의 등 지원하지 않는 요청에는 거래 입력만 가능하다고 안내한다.
- AI가 데이터베이스를 직접 변경하지 않는다. 구조화된 초안을 서버에서 검증하고
  사용자가 확인한 뒤 저장한다.
- 명세서 대조는 결정적인 규칙으로 후보를 찾고, 사용자가 확정한 변경만 반영한다.
- 업로드한 원본 명세서 파일은 영구 저장하지 않고 처리 완료 후 폐기한다.
- 첫 번째 클라이언트는 웹이며 홈 화면에 설치해 독립 창으로 실행할 수 있는
  PWA를 기본 모바일 경험으로 사용한다.
- 영수증 입력은 PWA의 카메라 촬영과 사진 선택으로 먼저 제공한다. 사진 앱의
  공유 메뉴처럼 신뢰할 수 있는 OS 통합이 필요해지면 기존 웹을 Capacitor로
  포장하는 방식을 우선 검토한다.

## 백로그

### 분류와 입력

- 입력 화면과 AI 초안에서 기본 분류와 태그를 추천하고 사용자가 수정 가능하게 구성
- 자동 분류보다 사용자가 확정한 기본 분류와 태그를 우선
- 결정적 규칙으로 분류할 수 없는 거래에만 AI fallback 추가

### 후속 기능

- PWA에서 영수증 촬영·사진 선택, 서버 OCR과 거래 초안 확인
- Gmail 결제 메일 수집
- iOS 단축어 거래 수집
- Android 문자·알림 거래 수집
- 공동 예산과 저축 목표
- 반복 지출 감지
- 알림과 일간 요약
- 사진 앱 공유 메뉴 등 OS 통합 필요가 확인되면 Capacitor 모바일 앱 검토
- OpenAPI 기반 TypeScript 클라이언트 생성
- Kakao 로그인과 기존 사용자 계정 연결
- Naver 로그인과 기존 사용자 계정 연결
- 실제 캐싱 또는 작업 조율 필요성이 확인된 경우에만 Redis 추가
