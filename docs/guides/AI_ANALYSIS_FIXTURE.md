# AI 가계 분석 더미 데이터 검증

기준 날짜는 서울 기준 **2026-11-24**다. `scripts/seed_ai_analysis.py`로 9월 84건,
10월 83건, 11월 1~24일 83건을 생성한다. 금액과 가맹점은 모두 가상이며 기존 거래는
변경하지 않는다. 두 결제자와 11개 카테고리, 카드·현금, 월초 00:00:00과 월말
23:59:59 거래를 포함한다. 내역의 `ai-analysis-fixture:v1:` 표시로 구분한다.

## 실행

Python 3.9 이상과 실행 중인 저장소의 로컬 Compose PostgreSQL이 필요하다. 스키마는
먼저 API의 기존 Flyway migration으로 적용하고, 한 번 로그인해 가구와 사용자를 만든다.
시드는 가구, 인증 계정이나 로그인 우회 기능을 만들지 않는다. Flyway와 운영 배포에는
더미 데이터가 포함되지 않는다.

데이터와 10개 질문의 기대값만 확인한다. DB 연결이나 변경은 없다.

```bash
python3 scripts/seed_ai_analysis.py --as-of 2026-11-24
```

가구의 실제 두 구성원 ID를 알고 있으면 명시해서 추가한다. 아래 ID는 현재 로컬에서
확인한 값이며 다른 개발 DB에서는 해당 가구의 ID로 바꾼다.

```bash
python3 scripts/seed_ai_analysis.py --as-of 2026-11-24 \
  --apply --household-id 1 --me-id 1 --partner-id 2
```

구성원이 한 명뿐인 개발 가구에서는 다음 명령으로 `[AI 더미] 배우자`라는 가상 구성원을
만들 수 있다. 이 구성원은 OAuth 인증 정보가 없어서 로그인할 수 없다. 기존 사용자의
인증 정보와 세션은 수정하지 않는다. 실제 구성원이 두 명이면 이 옵션 대신 `--partner-id`를
사용한다.

```bash
python3 scripts/seed_ai_analysis.py --as-of 2026-11-24 \
  --apply --household-id 1 --me-id 1 --create-dummy-partner
```

명령은 저장소의 `compose.yaml` 안 `postgres` 서비스만 대상으로 한다. 실제 환경변수
파일을 읽지 않도록 `--env-file /dev/null`을 지정한다. 현재 선택한 Docker context가
개발용인지 확인하고 실행한다.

같은 기준 날짜와 ID로 재실행하면 이미 있는 더미 거래를 건너뛴다. 한 트랜잭션 안에서
두 구성원의 가구 소속과 더미 데이터 집계를 검증하므로 검증 실패 시 이번 실행을 롤백한다.
다른 기준 날짜의 데이터가 이미 있으면 추가하지 않고 중단한다. 이미 수정하거나 삭제한
더미 거래가 있으면 기대값 검증에서 중단될 수 있으므로 테스트를 마친 데이터는 먼저 정리한다.

출력 앞부분은 **더미 데이터만의 기대값**, 뒷부분은 **기존 거래를 포함한 실제 가구의
기대값**이다. 기존 거래가 같은 기간에 있으면 실제 가구 결과가 달라질 수 있다.
가맹점 원문·실명·인증 정보는 조회하거나 출력하지 않는다.

## 검증 질문

웹에서 `--me-id`로 지정한 사용자로 로그인하고 통계 화면의 “우리집 지출에 물어보기”에
아래 질문을 입력한다. “이번 달”은 11월 1~24일, “지난달”은 10월 전체다. 날짜가 달라진
뒤 테스트할 때는 질문의 상대 날짜도 명시적인 날짜로 바꾼다.

| 번호 | 질문 | 더미 데이터 기대값 |
| --- | --- | --- |
| 1 | 이번 달 총 얼마 썼어? | 2,222,000원, 83건 |
| 2 | 지난달 총 얼마 썼어? | 2,162,000원, 83건 |
| 3 | 지난달보다 이번 달 식비가 얼마나 늘었어? | 260,000원 → 320,000원, 60,000원 증가 |
| 4 | 이번 달 내가 쓴 식비는 얼마야? | 160,000원, 10건 |
| 5 | 이번 달 배우자가 쓴 육아비는 얼마야? | 270,000원, 10건 |
| 6 | 이번 달 가장 많이 쓴 카테고리는 뭐야? | 주거, 850,000원 |
| 7 | 지지난달 총 지출은 얼마야? | 2,110,000원, 84건 |
| 8 | 2026-10-31 하루에 총 얼마 썼어? | 17,000원, 1건 |
| 9 | 2026-09-01부터 2026-11-24까지 총 얼마 썼어? | 6,494,000원, 250건 |
| 10 | 2026-06-01부터 2026-06-30까지 총 얼마 썼어? | 해당 거래 없음, `NO_DATA` |

9번은 최근 200건을 넘는 거래 전체를 집계하는지 확인한다. 3번은 이번 달이 아직 끝나지
않은 상태이므로 모델이 전체 월끼리의 비교나 미래 지출을 단정하지 않는지도 확인한다.
`ME/PARTNER`는 로그인한 사용자 기준이어서 배우자 사용자로 로그인하면 결과가 달라진다.
10번은 전체 가구에 해당 기간 거래가 없어야 `NO_DATA`가 된다.

답변 문장 일치보다 조회 기간·카테고리·결제자와 금액의 정확성을 확인한다. 성공 답변의
근거는 실제 조회한 거래여야 하며, 일부 근거 금액의 합이 전체 합계와 같을 필요는 없다.
10개 질문을 실행하면 기본 일일 한도 20회 중 10회를 사용한다. 실제 모델 호출에는 비용이
발생하고, 시드 명령 자체는 AI를 호출하지 않는다.

## 더미 거래 정리

필요할 때만 아래 SQL을 로컬 개발 DB에서 실행한다. 다른 날짜의 더미 거래와 기존 거래는
삭제하지 않는다. 가상 배우자도 아래 조건을 모두 만족할 때만 삭제하므로 실제 인증
사용자나 다른 거래의 결제자는 보존한다.

```sql
BEGIN;
DELETE FROM transactions
WHERE household_id = 1
  AND description LIKE 'ai-analysis-fixture:v1:2026-11-24:%';

DELETE FROM users u
WHERE u.display_name = '[AI 더미] 배우자'
  AND EXISTS (
    SELECT 1 FROM household_memberships m WHERE m.household_id = 1 AND m.user_id = u.id
  )
  AND NOT EXISTS (SELECT 1 FROM auth_identities a WHERE a.user_id = u.id)
  AND NOT EXISTS (SELECT 1 FROM transactions t WHERE t.payer_id = u.id)
  AND NOT EXISTS (SELECT 1 FROM stored_value_accounts s WHERE s.owner_user_id = u.id)
  AND NOT EXISTS (
    SELECT 1 FROM household_memberships m WHERE m.user_id = u.id AND m.household_id <> 1
  );
COMMIT;
```

가상 구성원을 만든 경우 실제 배우자 계정으로 테스트하기 전 정리한다. 시드는 실제
인증 계정과 가상 배우자를 자동으로 연결하거나 바꾸지 않는다.
